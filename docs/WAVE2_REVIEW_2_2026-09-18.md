## 3. Findings

### 3.1 New regression — the selected segment label is invisible until a chunk loads · P1

R7 removed framer-motion from the `ui` barrel by loading the thumb through
`next/dynamic` with **`ssr: false`** (`web/components/ui/segmented.tsx:5-8`).

The thumb *is* the selected background. `background: var(--color-accent)` was
moved off `[aria-selected="true"]`, which now only carries
`color: var(--color-on-accent)` and `font-weight: 700`
(`dashboard-nova.css:3147`). Until the dynamic chunk arrives — through server
render, hydration, and the chunk fetch — the selected label paints on the bare
track (`.ui-segmented { background: var(--color-surface) }`):

| theme | label `--color-on-accent` | track `--color-surface` | contrast |
|---|---|---|---|
| dark | `#04050E` (`:201`) | `#151827` (`:171`) | **1.15 : 1** |
| light | `#FFFFFF` (`:713`) | `#FFFCF6` (`:605`) | **1.02 : 1** |

Invisible in both themes, on every `Segmented` on the dashboard — the kit that
replaced seven hand-rolled controls. No gate sees it: the harness screenshots
after hydration, and the axe gate here only checks contrast on rendered state.

**Fix — one word.** Change `ssr: false` to `ssr: true`. `next/dynamic` still
emits a separate client chunk either way, so the barrel's client graph stays
framer-free and the ChunkLoadError incident stays fixed; `ssr` only controls
whether the component is server-rendered, which is precisely what is producing
the blank state. Verify afterwards that a route importing only `Card` or `Pill`
still has no framer in its chunk.

A CSS fallback background on the selected button is the obvious alternative and
is **not** recommended: the thumb slides between buttons, and `aria-selected`
flips synchronously with the state change, so the destination button would paint
its own accent instantly and swallow the slide.

### 3.2 DXA-16's source guard has a scope hole that matches the live failure

The guard (`web/lib/dashboard-motion-source.test.ts`) is genuine. It carries its
own matcher self-test, and an end-to-end negative control was run during this
review: a scratch file `components/dashboard-zz-scratch.tsx` containing
`transition: "opacity 120ms ease"` was added, the guard failed and named both
the file and the offending string, and the scratch file was removed. **That is
the negative control the pass did not run.**

But the guard scans 126 files and excludes:

- `app/globals.css`, `app/dashboard/dashboard.css`, `app/dashboard/dashboard-globals.css`
  — every dashboard CSS file except `dashboard-nova.css`;
- all `components/*.css` siblings;
- `components/ui/*.tsx` (including all four new primitives);
- `collapsible-section.tsx`, `modal-shell.tsx`, `drawer-panel.tsx`,
  `life-area-card.tsx`, `nova-select.tsx`.

With the blanket `*{…!important}` rule removed, the browser now reports the
unmasked truth (`verify-tabs-postfix`):

```
FAIL  DXA-16  transitions use the Nova easing tokens only   ease
```

13 live elements — settings ×9, personal ×2, family ×2 — all sourced from files
the guard cannot see:

| file | count | example |
|---|---|---|
| `app/globals.css` | 6 | `:1345  transition: all 0.14s ease` |
| `components/dashboard-guest-chart-modal.css` | 6 | `:89  transition: border-color 150ms ease, box-shadow 150ms ease` |
| `components/dashboard-feedback-modal.css` | 2 | `:57  transition: background 0.15s ease, color 0.15s ease` |
| `components/public-nav.css` | 3 | `:19  transition: opacity 120ms ease, visibility 120ms ease` |

Note the two `dashboard-`prefixed **CSS** files: the guard's
`/^dashboard-.*\.tsx$/` filter matches components only, so their sibling
stylesheets fall straight through.

Codex marked the item `[~]`, so this is not a false completion claim. But the
guard as scoped cannot be the mechanism that closes it.

**Fix:** extend the scan list to `app/globals.css`, `app/dashboard/*.css` and
`components/*.css`, then fix the hits. `ease-in-out`, `ease-out` and `linear`
remain legitimate and the existing regex already excludes them.
